# 决策记录

## 01-ui-shell

- **最小边界**：保持 NativeActivity + EGL/GLES 3，四页只提供布局、滚动、选择状态和空状态。不做输入法、导入、真实搜索、播放、下载或库数据；相关入口明确显示尚未开放，避免把预览当成可用音乐功能。
- **渲染方案**：参考同级 `CUIDemo` 的 SDF/批次思路，重新实现小型 C 渲染器，不搬入演示 UI、Vulkan、图片后端、FBO 和 damage 历史。静止不刷帧，变化时整帧绘制，正确处理 Android 不保留交换缓冲的情况。
- **字体**：离线生成 Noto Sans SC Regular 的 UI 文案子集，避免启动时在主线程读完整字体、生成 SDF 或引入大字体包。实机发现 stb 的 SDF 对 CFF 三次曲线不完整，因此明确拒绝 CFF，使用 TrueType 二次曲线字体。当前未知字符回退 `?`，真实歌名的动态 CJK 字形缓存留待对应功能条目。
- **安全区**：实机 targetSdk 36 下 `contentRect` 仍覆盖系统导航栏，不能仅依赖它。新增纯 C 框架 JNI 只读查询系统栏/刘海，与 contentRect 取交集；不为查询安全区引入 Kotlin Activity 或 UI。异常与返回值契约见 `BRIDGE.md`。
- **返回兼容**：在 Activity manifest 关闭 `enableOnBackInvokedCallback`，否则新 Android 默认预测返回会直接关闭 NativeActivity、绕过 C 的 `AKEYCODE_BACK` 处理。保留系统传统返回路径，本轮不加入 Kotlin 回调。
- **状态与返回**：每页滚动/分类留在内存，旋转不重置；系统临时恢复用版本化 POD `UiState`，不提前实现磁盘持久化。返回依次关闭提示、收起设置说明、回歌曲页、退出。
- **验证条件**：连接的 Android 15 真机可安装/启动/截图，但系统拒绝 adb 注入触摸（`INJECT_EVENTS` 权限）；交互与旋转验证使用本机 `aosp_17` x86_64 模拟器（SwiftShader GLES 3）。不修改真机安全设置来绕过限制。

## 02-lx-source-import

- **输入方式**：采用 C 按钮「粘贴导入」统一接收链接、JSON、整个文件文本。无 Kotlin 编辑框/对话框，无文件选择器、存储权限或 ContentProvider 文件读取。剪贴板受 Android 前台权限约束，必须在 Java 主线程读取，因此增加最小 NativeActivity 子类；解析与管理逻辑仍在 C。文件导入是复制文件内容，不是复制文件路径。
- **JSON 范围**：LX 标准交付物是 JS 脚本，并没有统一的批量音源 JSON 导入标准。本轮选择单脚本 `script` / `code` / `content` 字段或 JSON 字符串，严格解码后复用同一元数据解析。暂不支持第三方 sources 订阅、MusicFree 插件清单、LX `gz_` 压缩存储或 `.lxmc` 备份；给出格式错误而不猜测执行。无需引入 JSON/JS/压缩 SDK。
- **真实注释兼容**：依据 LX 自定义源文档及真实六音脚本，允许开头 BOM/空白、`/*` / `/**` / `/*!` 和未知标签。name 必填，其他四项可缺省；版本为任意有界文本，不强制 semver。仅导入存储，不能因为已启用而执行代码；运行时严格留给 03。
- **安全与资源**：UTF-8、NUL、JSON 深度、字段/正文/总量/条数均有界；只按内容拒绝重复，不因同名替换既有源。允许显式 HTTP 导入并在 README 提醒不加密，默认建议 HTTPS，拒绝 HTTPS 降级重定向、URL 凭据以及非 HTTP(S) 协议。元数据首页只是显示，不自动打开。仅接受可信脚本，为未来运行时保留安全提示。
- **持久化取舍**：32 个小集合采用自定义版本化 C 二进制文件，不引入 sqlite；单文件保存正文、ID、启用、顺序，元数据重新派生。工作线程原子替换、失败回滚、损坏拒绝写入，避免解析失败破坏已有音源。不做断电级目录 fsync/备份恢复；损坏文件可先通过调试工具备份，再清除应用数据，后续如需求扩大再升级存储方案。
- **生命周期**：busy 时拒绝追加命令，避免无界积压；退出设置取消位并 join 工作线程，无 detached C 线程残留。缩短 socket 超时、每次读/重定向检查取消，但 Android 系统 DNS 不承诺硬截止，这是当前最小系统 HTTP 桥接的限制。
- **JVM native 装载**：NativeActivity dlopen 不能替代 System.loadLibrary 的 JVM 注册；实测剪贴板回调曾因此找不到 nativePaste，已通过 Kotlin companion 显式装载修复，后续模拟器回调成功。
- **中文元数据**：仅原 UI 文案子集无法显示真实音源描述。针对本轮扩充到 GB2312 常用 6763 汉字及文案，保持纯 C SDF 渲染，代价是 16 MiB atlas/CPU 与同量 GPU 空间；不提前开发完整动态 Unicode 字形缓存，罕见字/部分繁体/emoji 仍回退。来源与许可不变，度量压紧到 <800 行。
- **发布边界**：版本仍为 0.1.0；只更新 02 验收，不增 workflow push 分支触发，不打标签/建 Release。本地构建 APK 仅用于验收，不作为本轮发布产物。

## 03-source-runtime

- **引擎选择**：vendor Bellard QuickJS 2025-09-13（MIT，原始归档及校验见 vendor/quickjs/README.md），可直接运行 ES6+/async/Promise，避免 duktape 的 Promise/现代语法兼容成本。不链接 quickjs-libc、不开放文件、进程或模块加载；资源限制不是 OS 安全沙箱，仍只执行可信脚本。上游原样大文件/生成表是 ≤800 行规则的第三方例外，自写 C/Kotlin 文件仍满足限制。
- **LX 与搜索边界**：官方 [移动自定义源文档](https://lxmusic.toside.cn/mobile/custom-source) 中常规源只有 musicUrl，local 可含 lyric/pic，搜索由宿主完成。PLAN 要求示例搜索，因此保留官方 `{source,action,info}` 请求形式，同时显式扩展 search 和自有 provider key；不宣称普通社区源会自动获得搜索能力，不修改 03 验收项或提前实现 04 的内置多源搜索。
- **最小能力**：提供 mobile/2.0.0、currentScriptInfo、request/inited/updateAlert 事件、HTTP 回调/取消、Promise job、setTimeout/clearTimeout、buffer UTF-8/hex/base64 互转。示例实际使用 buffer；本轮不引入未用到的 crypto（md5/AES/RSA/randomBytes）、zlib、Node/浏览器 API、multipart/二进制 HTTP。依赖这些能力的脚本会报执行错误，不保证真实六音等大型混淆脚本运行，也不偷偷回退为模板或伪造歌曲。
- **真实示例**：使用 Apple iTunes Search API 的公开 song 元数据和 previewUrl，无第三方聚合代理/密钥/会员解析。歌曲数组含真实名称、歌手、专辑、时长、质量标签和 HTTP 预览下载地址；质量诚实标记 preview-aac，不猜 bitrate。时长为完整歌曲元数据、音频只有短预览；无歌词则返回空 lyric。musicUrl handler 用真实 HEAD 验证地址，不下载音频、不提前实现缓存/播放。
- **执行入口与状态**：只在音源管理增加固定关键字 love 的显式自检，导入/启用/冷启动仍不执行；自检依次 search→首曲 musicUrl→lyric，标准源缺 search 时直说。每次 action 新建/释放 JS 上下文，牺牲初始化复用换取清晰生命周期和失败重试；本轮没有自由输入/聚合/去重/搜索页结果，下一条再接入运行时公共接口。
- **有界调度**：沿用单槽命令和单工作线程，HTTP/JS/IO 串行不持 UI 锁。每 action 32 MiB JS heap、512 KiB JS 栈、40 秒 JS 截止/取消中断、最多 32 个待处理任务/256 个累计任务/16 次 HTTP；响应与结果大小有界，搜索最多规范化前 30 曲并标记 has_more。同步系统 HTTP 期间不能并行执行 JS timer/cancel；系统 DNS/写 socket 不保证硬超时，见 BRIDGE.md。
- **发布范围**：保持 0.1.0、既有 workflow 和标签发布机制；不新增依赖 SDK/Java 源码/测试用例，不打 tag 或建 Release。本轮只勾选 03，不开始 04。

## 04-search

- **输入取舍**：保持输入框和软键盘为纯 C，字母/数字直接输入，中文/其他 Unicode 用系统剪贴板；另支持常用硬件按键。没有 Kotlin EditText/View、输入法 UI 或 InputConnection，不为搜索重构 NativeActivity。255 字节关键词足够当前搜索；完整中文 IME 不是本轮能力，不把粘贴包装成系统输入法。
- **并发与取消**：独立于单线程音源管理，新建后台协调器 + 最多四路搜索；所有启用源均尝试既有 search handler，标准 LX 源无 search 时单独提示。最新查询单槽覆盖旧查询，旧任务 join 后再启动新轮，避免反复搜索堆积线程和内存。取消使用原子代次及 Kotlin HTTP 检查点，不复用永久 closing 位；底层 DNS/socket 无法硬中断，UI 立即取消并丢弃迟到结果。
- **快照所有权**：后台复制启用脚本，8 MiB 总上限沿用存储限制；每个源执行后立即释放快照。独立 store_lock 防止搜索遇到删除/重排后的悬空指针，修改/保存可暂时阻塞后台快照，但不让 GL 等待磁盘 IO。最多四个 JS Runtime 的分配上限合计 128 MiB；不为降低冷启动开销引入共享 JS 上下文。
- **首批与分页**：每源取前 30 条、聚合最多 240 首、UI 每页八条，不自动请求后续远程页。现有示例不支持远程 page，贸然滚动自动翻页会重复联网/重复数据；采用有界首批 + 本地分页，用户可细化关键词重新搜索。去重按源内 id 或归一化歌名/歌手/专辑与相近时长，来源按设置顺序优先，排序按关键词相关度与稳定源顺序，不宣称完整 Unicode 模糊匹配。
- **播放边界**：04 的「点击进入播放」实现为保存任意结果的自包含歌曲/来源值并切到播放页，诚实显示尚未开放音频输出。该条不实现 05 的前台服务/通知/焦点，也不提前做 06 缓存或 07 完整播放器。当前 search 契约已要求 URL，因此本轮不额外持有每曲原始 JS 对象或执行 musicUrl。
- **验证与发布**：使用现有 x86_64 模拟器和真实 Apple 搜索接口验收，临时复制公开预览示例作为第二个源验证并发去重，另保留无搜索能力的源检验部分失败；设备私有数据先备份，临时验收数据不提交。未新增测试用例、Java 或依赖 SDK，版本仍为 0.1.0；不改 workflow、不打 tag/建 Release，只勾选 04。

## 05-playback-service

- **系统边界**：按本条明确要求固定 Media3 1.8.0 的 exoplayer/session 两个 Android 托管库，用于解码、AudioTrack、焦点、MediaSessionService 和系统通知；不是新增大型原生 SDK，不引入 Compose/View UI、Java 源码或额外 JS 桥。队列、选曲、自动下一首、seek 边界、状态快照仍为 C；Kotlin ForwardingPlayer 只把系统控制转交 C，再通过 Handler 下发原始 ExoPlayer，避免双份队列业务。
- **URL 与队列范围**：直接播放既有 search 契约必填的 HTTP(S) URL，不重构 03/04 保存所有原始 musicInfo 或重复请求 musicUrl，不宣称标准 LX 源自动具备搜索/完整歌曲解析。示例仍是短预览。点击某项以当前可见页（最多八首）替换队列，选择之后的新搜索、分页、删除音源都不改变该队列；不提前实现 07 的队列页/随机循环/封面/拖动进度。播放页只放本轮验收必要的按钮、10 秒 seek 和实际时间。
- **顺序策略**：切歌自动播放，首曲上一首回到开头，末曲下一首不循环；自然结束在有下一首时切换，末曲结束暂停，点击播放重播当前曲目。C 队列 API 上限沿用 240，UI 仅复制可见页，内存有界；替换释放旧队列。加载代次同时校验状态与自然结束，迟到事件不能覆盖新歌曲。
- **生命周期与后台**：播放单例是进程级状态，不持有 Engine、NativeActivity、脚本或 HTTP context；解码/网络由 Media3 后台线程处理，C 不另起空转工作线程。Activity 暂停/退出只解绑 looper，服务继续播放；重开界面从 C 恢复当前曲目和进度。强制停止/进程死亡后不持久恢复队列，不擅自后台自启；队列持久化不混进本轮。
- **通知与焦点**：NativeActivity 没有 MediaController，服务主动 addSession，确保用户直接选曲后也有前台提升与媒体通知。系统通知不需要申请普通通知授权；Media3 自动音频焦点管理避免重复请求，瞬态失焦恢复时续播、永久失焦后可手动继续。拔耳机暂停；系统前台提升拒绝、网络/解码失败均可读提示并前台重试，不绕过系统后台限制。
- **发布边界**：版本保持 0.1.0；不修改 workflow、不新增测试用例、不打 tag/建 Release，只勾选 05。本地 APK 只用于验收，不上传为发布产物。

## 06-cache

- **显式下载与满额策略**：播放页手动缓存当前歌曲，不自动下载整个队列、不提前实现仅Wi-Fi策略。默认1 GiB，用户可选256/512/1024/2048 MiB；满额拒绝新下载而不自动删除用户留存的歌曲，降低到占用以下也拒绝。最多512条、单曲2 GiB，满足有界离线缓存，不引入sqlite/下载SDK或后台下载服务。
- **C与系统边界**：C持有所有索引、身份去重、容量、路径命名、状态与分页；Kotlin只封装系统HTTP和MediaStore、旧系统权限。缓存工作线程同步调用系统流式IO，32 KiB块，不用原来限2 MiB的文本HTTP桥、不把音频ByteArray送回C；没有Kotlin业务队列/UI或Java文件。
- **系统兼容**：API29+ MediaStore公开Music路径，pending完成后发布，不请求读取整个媒体库。API26–28按需请求WRITE_EXTERNAL_STORAGE，授权后用户显式重试，公共part改名后登记DATA，播放仍统一content URI。没有额外权限回调或授权等待状态机；拒绝授权可继续在线播放。旧系统分支本轮无法实机覆盖，已记录为兼容风险。
- **身份与格式**：同一来源/音质按ID去重，缺ID按元数据与相近时长；不把易过期的URL当歌曲身份，也不跨源猜测同曲音频等价。扩展名优先URL再音质，未知默认m4a（当前示例为AAC容器），不是通用格式转换/音频校验器；网页/空内容/长度不完整会拒绝，未知二进制或损坏音频在Media3播放失败时提示。路径清理保留常用Unicode、缩短长名，同名不同身份让系统附数字，绝不覆盖已有公共文件。
- **播放生命周期**：冷启动从缓存管理选曲，不要求联网搜索，原音源被删除也可播放缓存列表；现有队列不跨进程持久化。Activity退出取消未完成缓存但不停止播放服务，保留进程内查找表供通知下一首命中。删除当前输出不主动停止播放，打开FD的行为由系统决定；外部删改用启动探测/检查文件修复，播放本身不在GL/主线程探测磁盘。
- **一致性边界**：私有索引原子替换、正常下载失败清理新公共文件、删除后的旧索引启动修复；不引入跨MediaStore/私有文件的事务日志。在公共文件发布后、C索引rename前被强杀可能留下未索引完整文件；不在启动时擅自删除这些可见音乐。卸载/清数据不扫描重建旧公共音频，用户可在系统文件管理器管理，避免申请读取所有媒体权限。
- **发布范围**：只勾选06，README仅更新功能/使用，其余架构和桥接写docs。版本仍0.1.0，workflow不变，不新建测试/Java/SDK，不打tag或建Release；本地验收APK不上传为发布产物。

## 07-player-ui

- **封面契约**：在既有扩展 search 歌曲中增加可选 `cover` HTTP(S) 字符串（≤2047字节），示例使用 Apple 的 artworkUrl100；不猜测其它平台 img/pic 字段、不额外执行 LX pic handler。缺失、无效地址、解码/联网失败回退音符，不阻止歌曲播放；只有显式重试才重新请求，加载期间不提供重试按钮。
- **纯 C 图片路径**：vendor 与同级 CUIDemo 一致的 stb_image v2.34（来源、校验、双许可见 vendor/README.md），只编译 JPEG/PNG；下载上限2 MiB、原图边≤2048/像素≤4 Mi、输出最长边≤512。系统 HTTP 字节传输是最小 Kotlin 桥，所有缓存/解码/缩放/GL/UI 在 C；不引入 Bitmap、图片SDK或Java。第三方原样头文件沿用vendor行数例外。
- **有界封面缓存**：URL 的 FNV-1a64 选64个私有槽，槽内完整URL比较避免碰撞误图，保存缩放RGBA（每槽≤1 MiB+约2 KiB头），碰撞替换不做额外LRU。不是公共音频配额的一部分，清空音频不清除封面；清除应用数据时一起移除。此取舍省掉额外索引与原图重复解码，不保证永久保存所有历史封面。CPU只保留当前图用于EGL重建，切地址先清旧图，代次拒绝迟到结果。
- **索引兼容**：为了离线曲目冷启动仍能找回封面，SourceSong追加cover并把缓存记录升级为LXCC v2（5928字节）；仍沿用旧文件名，显式定义/静态校验v1布局（3880字节）逐条迁移读取，下一次写入才原子升级，损坏仍只读保护。再次缓存已有曲只补封面地址、不重下音频；不通过改sizeof悄悄丢弃旧条目。不承诺旧APK读取v2，降级需自行备份索引。
- **进度与模式**：拖动期间只预览，松手一次seek，取消/失焦/旋转不提交；未知时长禁用拖动，切歌使旧代次手势失效。保留精确到音频时长末尾的seek语义，播放中seek到终点允许按模式自然结束/切歌，不人为减掉一秒。四模式仅进程内保留；随机只保证连续不重复当前曲，不是整队列无放回洗牌，上一首使用至多队列长度的历史。
- **手势与系统边界**：上滑封面展开队列，普通控制区仍可滚动；队列顶部下滑/按钮/返回收起，左右切歌为可选项，本轮不实现以免与seek冲突。只做200ms级封面入场/淡入、队列滑入及前台播放页平滑进度；暂停静止停止刷帧。硬件音量交给系统媒体流、输出跟随系统，不加独立音量滑块或设备选择器，不提前开发08收藏历史歌单。
- **发布范围**：只勾选07，版本仍0.1.0，workflow不变、不新增仓库测试或Java文件，不打tag/建Release；本地APK只验收、不上传发布。

## 08-library

- **最小存储**：沿用纯C版本化私有文件，不引入sqlite或托管业务层。全库共享1024个歌曲值，收藏/历史/歌单仅存ID；每次修改约5.32MiB的有界原子快照，换取无跨表事务/日志依赖。64槽FIFO、后台IO/过滤/分页、修改失败回滚、坏文件只读保护；不实现同步、导出备份、断电级目录事务或公共媒体扫描。
- **后台历史生命周期**：若随Activity stop/join会遗漏通知切歌，因此库worker有意常驻到进程退出。它不持Activity/JNI指针，UI只订阅acquire/release的looper；静止cond等待，退出Activity仍可保存后台实际播放。首次STATE_READY且isPlaying才记，同generation暂停恢复不重复，失败加载不记；强杀发生在未确认写入期间可能丢最后操作，用户以保存成功消息为准。
- **库与缓存不同**：库以来源+歌曲ID（缺失用元数据/时长）识别歌曲，忽略音质/易变URL，避免不同音质重复收藏；缓存仍按音质区分音频文件。重复添加拒绝、历史置顶最多200首、移除仅删当前列表关系；收藏512、歌单32×240、全库1024首，容量满时明确拒绝而不静默删收藏/歌单。
- **交互边界**：播放页收藏/取消、选择歌单添加；歌曲页创建/改名、浏览/本地搜索和删除。名称与本地关键词复用纯C字母数字键盘和现有系统短文本剪贴板，中文用粘贴，无Kotlin UI/新JNI签名。歌单名字去首尾空白并忽略ASCII大小写去重，搜索不做全Unicode折叠。列表六项一页，点击当前页替换队列；不把库浏览改成全库加载入队或跨进程恢复队列。
- **远程地址**：不在08重构音源执行契约为每次重新musicUrl解析；库保存原搜索的元数据与直链，命中缓存可离线播，远程签名过期需重新搜索并播放/添加更新。收藏/歌单操作不自动缓存音频；删除歌单不删除公共音频。
- **发布范围**：只勾选08，README只描述功能/使用；架构/格式/JNI说明归docs。保留0.1.0及既有标签触发workflow，不开始09/10，不新增测试用例、Java或SDK，不打tag/建Release。

## 11-system-ime

- **边界**：采用白名单内约1dp透明EditText作为系统输入目标，复用标准Editable/InputConnection协议，不自写输入法、不加入可见Kotlin页面或对话框。C显示正文/组合下划线/光标选区，负责触摸和提交；两套自绘字母键盘删除，避免维护两种不一致编辑语义。硬件输入也交系统，不再C重复映射ASCII。
- **传输**：全文快照而非commit/delete增量，携带UTF-8字节选区与组合区、单调session，主线程到C互斥邮箱合并文本并保留提交/关闭标记。成本上限2KiB，换取代理对、拼音重组、选区删除/粘贴一致性；不改变搜索/音乐库后台契约。搜索/名称仍255字节，新增地址框2047字节；整脚本/JSON沿用原2MiB粘贴入口。
- **纯C选区菜单**：透明输入目标不能给可见C框提供系统浮动工具条，因此C做点击光标、横向拖选与激活后长按「全选/粘贴」，粘贴本身调用系统EditText菜单动作；系统键盘的剪贴板、硬件Ctrl+A/C/V也可使用。暂不引入自绘拖柄/复制剪切工具条或完整双向文字排版；罕见字/emoji仍受既有SDF字体覆盖限制，数据传输不截断Unicode。
- **布局兼容**：新系统adjustNothing + Type.ime，旧系统adjustResize + visible frame/system insets后备；C与安全区求交且扣掉框架已resize部分。短屏编辑隐藏大标题、压缩底栏、自动滚到输入框。实测旋转可能重置TextView的EditorInfo选项，因此在每次onCreateInputConnection显式写NO_EXTRACT_UI/NO_FULLSCREEN；零inset延迟确认，防止旋转中误关闭输入连接。为分屏补screenLayout就地处理及未获焦resumed窗口的dirty重画，不扩展13的转场/预测返回。
- **验收实话**：模拟器Gboard中文候选/真实搜索、中文歌单命名/粘贴、音源URL回车错误、横屏和分屏输入已验证。Android15真机可安装启动但系统禁止adb触摸，搜狗中文操作无法自动完成；API26–29未有设备覆盖。记录为设备兼容复核风险，不宣称已通过真机验收、不修改设备安全设置、不添加或上传本地测试内容。
- **交付范围**：仅11，版本仍1.0.0，12/13/14保持未开始；无新增测试/Java/大型SDK，workflow和标签发布机制不变，不手动打tag或建Release。跨进程草稿保存、系统媒体浏览与完整App体验留给对应后续条目。

## 12-media-services

- **系统适配而非Kotlin业务层**：继续固定Media3 1.8.0，不新增SDK/UI/Java。MediaLibraryService暴露C目录；队列/身份/搜索结果/模式/选曲/恢复仍在C，Kotlin仅转MediaItem、异步Future、音频输出和订阅通知。ExoPlayer完整队列是系统时间线镜像，不是第二份决策状态机；pauseAtEndOfMediaItems阻止自行续播，再由C按generation处理自然结束。
- **最小目录与对外边界**：根包含搜索结果/收藏/歌单/最近播放/当前队列，搜索仅浏览应用本进程已有结果，不从车机请求执行音源脚本或增加新的网络搜索策略。开放标准控制器，无包名白名单以兼容车机/第三方；相应意味着连接者可读歌曲目录/控制播放，README明确提示。只接收本库mediaId，不接收任意URI或队列编辑，重复/过期ID失败；搜索和队列使用独立revision/serial，系统seek带serial防止旧索引选错新曲。
- **分页与legacy**：现代MediaBrowser每页1..100，库/搜索直接读取内存快照；legacy未分页订阅由适配层分成100项查询再返回最多512项，这是平台旧协议的有界兼容例外，不把全库一次加载进C UI。外部选曲采用所选歌曲所在的最多240首窗口，避免为了512首收藏扩大既有播放状态机容量。最多128项订阅、每秒至多一个后台刷新任务，不开新网络线程。
- **冷启动保留完整队列**：新增C进程级睡眠worker保存最多240首/索引/模式/位置，不仅保存当前曲，保证下一首可用；250ms合并控制操作、播放每5秒保存。只恢复暂停状态，不保存/自动重放播放请求、随机历史或搜索结果，不在进程重建后擅自发声。临时文件+fsync+rename，不做目录事务/备份迁移；损坏忽略，写失败日志并下次重试，强杀可丢最后未落盘操作。
- **无Activity也可用**：服务executor只读加载现有缓存索引并幂等启动库/队列worker，cache只恢复查找而不探测公共文件。额外保留一份5.32MiB已提交库快照，换取媒体查询不争用磁盘IO锁、不读未完成事务。缓存文件外部失效/远程URL过期仍沿用已有重试提示，不引入媒体库扫描/自动解析新直链。
- **唤醒及系统音频**：通知/客户端SessionActivity统一OPEN_PLAYER，经C邮箱切页；Activity选singleTask而不是仅依赖调用者的SINGLE_TOP，避免不同action唤醒创建两个共享静态Engine的NativeActivity。这是媒体入口生命周期修正，不提前加入13的预测返回/转场。焦点/瞬态恢复/ducking/noisy/路由继续交Media3，新增MediaButtonReceiver用于系统媒体键恢复，尊重强行停止和后台前台服务限制。
- **验收边界**：构建、真机会话可见、模拟器adb媒体控制/自然续播、5首队列与位置冷恢复（包括只起服务）、GSM暂停恢复已验证。没有可直接运行的独立MediaBrowser客户端，也未连接物理蓝牙/车机；拔耳机受保护广播不可由shell发送，未伪造验收或绕过系统安全。以上设备/协议端到端复核记录在ARCHITECTURE.md，不冒充全部真机验收通过。没有编写/扩展测试用例或上传本地验收数据。
- **交付范围**：只勾选12，13/14不开始；版本保持1.0.0、workflow触发不变，不手动打tag或创建Release，普通提交不发布安装包。
